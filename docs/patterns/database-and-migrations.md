# Database and migrations

## Schema

One table per file in `src/infra/database/drizzle/schema/`, exported from `schema/index.ts`:

```ts
export const taskStatusEnum = pgEnum('task_status', taskStatuses)

export const tasks = pgTable(
  'tasks',
  {
    id: uuid('id').primaryKey(),
    ownerId: uuid('owner_id')
      .notNull()
      .references(() => users.id, { onDelete: 'cascade' }),
    title: varchar('title', { length: 120 }).notNull(),
    createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
  },
  (table) => [index('tasks_owner_id_created_at_idx').on(table.ownerId, table.createdAt.desc())],
)

export type TaskRow = typeof tasks.$inferSelect
export type NewTaskRow = typeof tasks.$inferInsert
```

- Columns in `snake_case` with an explicit name; properties in `camelCase`.
- `uuid` primary keys generated by the domain (`UniqueEntityId`), not by the database.
- `timestamp(..., { withTimezone: true })` for every date.
- Enums come from the domain's `as const` list, so the TypeScript union and the database enum cannot drift.
- Schema files import other files **relatively** (not `@core/*`): drizzle-kit loads them outside of Nest.
- Add an index for every `where` + `order by` a list uses.

## Migrations

```bash
npm run db:generate -- --name add-due-date   # writes drizzle/<timestamp>_add-due-date/migration.sql
npm run db:migrate                           # applies pending migrations to DATABASE_URL
```

- **Never write or edit a migration by hand.** Change the schema and generate. If the generated SQL is wrong, fix the
  schema and generate again.
- Review the SQL before committing: a renamed column may come out as drop + add.
- CI fails when the schema changed and the migration was not generated.
- In production, the image runs `node dist/infra/database/migrate` (drizzle-orm's migrator; drizzle-kit is a dev
  dependency) before the new version starts.
